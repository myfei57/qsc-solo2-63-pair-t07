# 载重配载：越限处置策略抉择

## 背景

行李上转盘前必须先过秤。超重的、重心偏向一侧的件要在进舱前挑出来，而不是
等装机时才发现。配载系统按"载重上限 + 重心窗口"两条约束自行排出装载顺序：
先装哪些、越限时拒哪一件，并给出可核验的拒绝理由。称重记录、额度账与转盘
装载逐笔可核，越限与拒绝的结论同步进入导出件与哈希链接的审计留痕。

候选件逐件试装时，如果把它叠到当前已确认前缀上会突破载重上限或重心窗口，
有两种处置思路都讲得通：

| 维度 | A. 越限时拒掉最后一件（reject_last） | B. 用较轻件换装（swap_lighter） |
| --- | --- | --- |
| 动到谁 | 只动尚未确认的触发件，已确认装载一律不撤 | 从已确认顺序里回滚一件更重的，让较轻的触发件顶替 |
| 对旅客的影响 | 触发越限的旅客在登机口才被告知行李拉下，行程确定性差；但更早确认的旅客零打扰 | 被撤重件的旅客需要更早被分流改签（行李未真正装机，比装机后再拉下代价小）；触发件旅客能成行 |
| 对配载/装机的影响 | 装机端零返工；但货舱既有的偏重/偏满排布无法被后到轻件改善，舱位利用率低 | 装机端有一次撤板/重装返工；多保一件上机，舱位与重心排布更优 |
| 系统复杂度 | 低：只给触发件一笔拒绝 | 高：要回滚已确认顺序，并对回滚后的整段顺序重新验证 |
| 适用场景 | 截载临近、登机口已关闭、没有撤板窗口 | 仍有撤板窗口（航班 open/boarding、装机未封闭） |

## 抉择

**默认采用 B：用较轻件换装（`swap_lighter`）。** 理由：

1. 题述明确要求"换装要能回滚已经确认的装载顺序，回滚后重心窗口与载重上限
   的一致性仍要同时成立"——选 B 才能让这条硬约束在系统里真实成立、可测。
2. 行李此时尚未真正装机，回滚的只是"已确认的装载顺序"，撤一件重件的成本远
   小于装机后再拉下；且 B 多保一件上机，对旅客整体成行率和货舱利用率更优。
3. A 不是被删掉，而是作为可切换策略保留（`/api/load/policy` 设为
   `reject_last`），用于没有撤板窗口的临近截载场景。B 找不到可行换装时
   自动退化为 A（拒绝理由码 `no_feasible_swap`，并在 `detail.swap_attempted`
   标明已尝试换装）。

## 代价（必须随结论说清楚）

选 B 相对 A 多付的代价：

* **配载/装机返工**：槽位上的重件及其后已确认件要按后入先出撤板。系统为每
  一件撤板动作各写一笔 `rolled_back` 留痕（`detail.resume` 标明该件撤板后
  是否原位恢复），撤下的重件单独记 `pulled_off`，交人工改配后续批次/航班。
* **旅客沟通提前**：被撤重件的旅客会比"装机后拉下"更早被通知改签。这是用
  更早、更可控的打扰换掉登机口的被动甩客。
* **一致性校验成本**：换装不是"换完看最终总量"，而是对换装后的整段装载顺序
  逐前缀重新验证载重上限与重心窗口；任一前缀不过，整组换装不落账。

A 的代价（切换为 `reject_last` 时承担）：

* 触发越限的旅客最晚知情、成行率最低；
* 已有的偏重/偏满排布无法被后到轻件改善，舱位利用率与重心余量都更差。

## 关键语义

* **原子换装组**：`rolled_back × n` → `pulled_off`（减载重）→
  `swapped_in`（加载重）在同一个存储会话提交，要么组内全部可见，要么整组
  不见。注解行（rolled_back）携带组提交后的最终账面合计，账态迁移只发生在
  `pulled_off` 与 `swapped_in` 两行，载重账可按 `delta_g` 逐笔对账守恒。
* **换装槽选择**：撤下的确认件必须严格更重（"用较轻件换装"），换装后的
  顺序为"去掉槽位件、触发件排到队尾"，且逐前缀都满足两条约束。选满足条件
  的最轻件、同重取位序最靠后，把撤板深度与扰动压到最小。
* **回滚后一致性**：`plan_batch` 对最终顺序跑 `prefixes_hold`，编排器落账
  前再复核一次；不通过则抛错、整组回滚，账上的顺序永远可行。
* **不重复计重**：已在载重账上的件（`confirmed`/`swapped_in`）和已有终态
  拒绝的件，在任何批次再提交一律判 `already_counted`；`pulled_off` 释放其
  载重占用，但仍标记为"已给过结论"，是否重投由人工决定，系统不会自动把它
  算回同一航班，避免重复计入。
* **缺秤件处置**：无称重记录（或重量非正）的件不进策略层，直接判
  `missing_weight`/`invalid_weight`，理由文本要求"退回补秤、复核后可重新
  提交"。这两个原因不是终态：补秤后重新提交可正常确认。
* **逐笔可核**：称重（`weighing.put`）、额度包线（`envelope.put`，带版本）、
  配载结论（`load.decision`）都是只增日志命令，重启重放后载重账与装载顺序
  完全一致；每笔结论同步写一条哈希链接审计条目（复用全链路 audit 链与
  `digest_of`），并在导出 CSV（`weighings.csv`、`loadplan.csv`）中原样携带
  `kind`/`reason`/`policy`/余额与合重心。

## 拒绝原因码

| 原因码 | 含义 | 是否终态 |
| --- | --- | --- |
| `missing_weight` | 缺称重记录，退回补秤 | 否，补秤可重投 |
| `invalid_weight` | 秤量非正，复核秤台 | 否 |
| `piece_overweight` | 单件超本航班单件上限 | 是 |
| `deadload_exceeded` | 装入后业载超上限 | 是（本航班） |
| `cg_out_of_window` | 装入后合重心偏出窗口 | 是（本航班） |
| `already_counted` | 已在账/已终态拒绝，跨批次不得重复计重 | 是 |
| `flight_not_plannable` | 航班已关闭或未配包线 | 视航班状态 |
| `no_feasible_swap` | 越限但无更重确认件可换，退化为拒最后一件 | 是（本航班） |
| `pulled_off_for_swap` | 换装被撤下的合法件，交人工改配 | 否（转人工） |
